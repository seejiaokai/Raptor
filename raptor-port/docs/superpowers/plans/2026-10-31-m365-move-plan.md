# The M365 move plan — the SWiFT kit set against Raptor (31 Oct 26)

**What this is.** Every point of the SWiFT build-and-deploy kit — the guide for apps the PPCoE puts on MINDEF M365 — set
against Raptor as it is today, as a numbered work list in the order we recommend. It is written in Raptor's own words;
the kit's own files are not copied into this public project.

**Set aside on his order (D1530):** all the kit's red flags (whether the flying schedule or the Tracker count as
operational information among them), its rule against hosting on Vercel, and its rule that the GitHub project be
private — none of them is on the list below.

**How to use it.** Strike any point you will not follow by its number ("strike 11 and 29"); everything else is the plan.
Points marked **his call** need your decision; the rest are technical, and the agent decides and tells you. Nothing on
this list is built yet — each point is built only once you say so.

**The kit's second road** — a container on a separate cloud — is not for Raptor: it allows no personal data, and Raptor
holds names. Raptor takes the M365 road: a Power Apps code app, its tables in Dataverse.

Sizes: **small** = under a day of agent work · **medium** = a few days · **big** = a week or more.
When: **now** · **with the database step** (at the end, once the features are built — D473) · **at hand-over**.

## 1. Already fits

1. **One doorway for every save.** No screen touches storage directly; the database version slots in behind the
   doorway and the screens do not change. *(evidence: `src/storage/backend.ts`, its contract tests)*
2. **The table list is written on our side** and kept up to date with every change that adds something saved (D473).
   *(`docs/data-model.md`, `docs/data-schema.md`)*
3. **Who may do what is written per table, by role**, and the app asks one list that a test keeps in step with it; the
   screens are a mirror, the database is to enforce (D200). *(`docs/data-model.md` §11, `src/state/perms.ts`)*
4. **Nothing is loaded from the internet while the app runs** — no outside fonts, scripts, pictures or tracking.
   *(`index.html`; no web requests in `src/`)*
5. **Screens switch inside the app**, never by changing the web address. *(`src/ui/Shell.tsx`)*
6. **Few packages:** two run inside the app (React); the rest only build and test it. *(`package.json`)*
7. **Only made-up data is shared with the AI** — no real records, real names or pictures of live systems; testing
   against real tables later is point 36.
8. **Every record has a hidden id**, never a name or a position (10 Sep 26). *(`docs/data-model.md` §2)*
9. **A removal is a hidden mark, never an erase;** a person is never erased (D287, D290). *(`docs/data-model.md` §2)*
10. **Made-up data only** in the project; no real names; the demo store is cleared before the database (D54, D56).
11. **No keys or access codes in the app, and it stores no password.** The two demo sign-ins do check made-up
    passwords written into the code (D223); they go at the database step (point 25). *(`src/state/accounts.ts`)*
12. **A refused or failed save says so and stops** — never a silent loss, never a fall back to demo data
    (`[DB-READINESS]`). Other failures are point 11. *(`docs/handover-dataverse.md` §What happens next)*
13. **Rules have tests**, and browser tests run every screen at phone and desktop width (the gates).
14. **No AI inside the app**, so the kit's approval for apps with AI in them does not apply.
15. **No link leaves the app**, so the kit's rules for outside links have nothing to apply to.
16. **Everyone has a defence M365 account** (D165), which is what the M365 road needs.
17. **Notifications are to go through Teams** at the database step — an M365 service, not an outside one.
    *(`docs/handover-dataverse.md`, the access-request bell — D216, D227)*
18. **After hand-over, changes reach the live app only through the IT side's copy and its review** — what they told
    you on 29 Sep 26 (`[IT-QUESTIONS]`), and the same shape as the kit's.
