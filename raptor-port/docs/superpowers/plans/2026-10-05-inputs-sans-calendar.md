## 1. Outcome and retained boundaries

One Inputs entry opens a useful month calendar. Member Inputs and SANS Availability are two views of the existing input records; Calendar is primary and the current List remains available. A date opens its entries and an add action. Desktop users can drag a date range; phone and keyboard users have an explicit Select dates mode. SANS dates show how many people have offered Fly against the admin's required number, shortage colour, and an optional day/night flying indicator.

Source-grounded retained contracts: Inputs are global by real date/year, not week-local. Existing input commands, date validation, late marks, medical/document/OIL prompts, schedule re-projection, issued-face freezing, pending changes, sign-offs and undo stay authoritative. SANS offers remain one record per person per covered day, with one time window shared by Fly/AMT/OFT flags. Members add/edit/delete their own only; admins can file for others; other people's editors remain read-only per D364. The existing member default is their own inputs, Everyone one choice away. No repeated-week feature, day-lock bypass, automatic scheduling, changed availability gate or new per-activity requirement.

D570: Fly-only daily demand. D571: colour follows deficit. D572: count a Fly person once even for a short offer, and show hours. D577: sun means day flying, moon night flying, never weather or availability halves. Existing AM 00:00–12:00, PM 12:01–23:59, Custom overnight meaning and all-day meaning remain. Remarks has no placeholder in the new entry flow. Existing list exports and medical view stay reachable. The separate caps/ops task remains cancelled as immediate work; no prior-date SANS coverage repair rides this change.

## 3. Interaction and surface contract

Keep the incumbent dark shell, fonts, palette, button sizing and split CSS cascade. Do not rebrand. Desktop keeps seven date columns and a day detail panel/card; phone keeps seven columns, compact readable counts and a scrolling month. Existing crowded Member Inputs cells keep their content-first growth and capped input chips. SANS cells show date, optional sun/moon, offered/required, shortfall text; on phone the legend expands the compact labels.

Calendar/List and Member Inputs/SANS controls must be usable in both views. Calendar stays inside the Inputs context with app navigation/Undo reachable; do not leave the new primary view inside an inescapable full-screen overlay. If retaining the existing fixed overlay for minimal change, its header must supply the app's existing exit/navigation route and meaningful Back to list/Calendar choices, with accessible names; the phone topbar may not be obscured. Medical back returns to the previous Inputs mode/view rather than silently changing it. Existing table scroll and filters survive the Calendar round trip.

Day details: heading/date and close stay reachable; + Input or + Commitment before rows. Every row shows person, type/activities, all-day/AM/PM/custom hours, remarks if present, existing late mark when applicable. Other-person rows open read-only. In SANS, summary is everyone; separate line explains any active row filter. Admin day controls: required people (blank allowed), flying period, Save, Clear target. Colour settings have amber/red numeric controls and a written live explanation of their boundaries; save atomically, cancel writes nothing. No control commits on half-typed input.

New input editor reuses existing date, person, type/activity, standard time, document and conditional prompt machinery. Do not rewrite the medical or OIL workflow. Blank Remarks means no placeholder, not removal of saved remarks. A saved row appears on its date and in List; if a filter would hide the new row, reveal/identify it by the existing pin/reveal convention without altering the count.

Date selection is one operation with one result:

1. Ordinary touch preserves vertical scroll, horizontal month swipe, stationary hold-to-add, chip hold-drag/move and popover gestures. A short ordinary tap still opens a day.
2. On a mouse, primary-button drag starting on empty day background selects an inclusive range after movement reaches a different day; it never pages the month. Starting on an input chip, note, puck, existing button or form element remains that control's operation. A still click opens its day. Suppress hold-to-add once range-drag starts; consume release click so it opens exactly one prefilled editor, not a popover as well. Do not reinterpret right-click as selection.
3. Select dates is available at every width and by keyboard. It displays an instruction and Cancel; first date anchors, second ends (normalize reverse order). Month arrows may be used between picks without losing the anchor. Selection shows start/end and Add input/commitment, so it does not save until the ordinary form does. Touch scroll remains active; chip drag is disabled only inside this explicit mode and returns on exit. Escape cancels selection before leaving the calendar. Keyboard day buttons use Enter/Space; no pointer-only route.
4. Mouse range stays within visible month cells; crossing months uses Select dates plus arrows or the existing form date picker. Leaving the grid without a valid release, pointercancel, navigation away, mode change, sign-out or lost pointer cancels without a write. Do not create a destructive range action.
5. Selecting several dates seeds one ordinary multi-day Input, not separate records. Existing overlap/date/published checks cover the entire range atomically. An overnight Custom offer stays anchored to the same dates as existing SANS records; do not credit the next date merely because its end clock is earlier.
