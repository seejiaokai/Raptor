Rulings/backlog search found the generic flow/keyboard/mobile/button aspiration, but no design answering these questions. Do not reopen settled button sizes, Undo placement, Board day arrows, no row-control collapse, or the specific pending Admin display proposal by accident.

1. Which everyday task feels slowest: preparing a day, correcting it after publication, or switching between areas? Recommend starting with preparing a day end to end, then reviewing the other routes.
2. Should the first visual proposal cover Edit Schedule and the Board together, or start with another area? Recommend those two together so a person can switch between them without relearning the same action.
3. For keyboard work, is the priority moving through existing fields quickly, or adding named shortcuts? Recommend field-to-field navigation and predictable Enter/Escape first, keeping multiline remarks intact.
4. On a phone, is the greater problem reaching frequent actions, keeping the edited field above the keyboard, or losing one's place between screens? Recommend keyboard visibility and retaining place first; move buttons only in approved pictures.

These are proposed questions, not answers or build authorization. Adapt them to the user's first answer rather than forcing all four if the real problem becomes clear earlier.
