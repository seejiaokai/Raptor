## Findings
1. The tests prove none of the readings the trial depends on (bar's visible-top correction, past, row): a broken copy with bar = b.top, past = 0, row = 0 passes all five (mut.test.ts). Cause: offsetTop always 0, scrollY never negative or past the foot, no pinned row drawn; jsdom scrollHeight 0 makes every frame read past 874 unnoticed. Fix: tests (a) offsetTop 29 / barTop 0 → bar −29, offsetTop 0 / barTop 29 → bar 29; (b) scrollY −12 → past −12, scrollHeight 1402 innerHeight 874 scrollY 540 → past 12; (c) a qsticky-head 49 below the bar's top → row 0, 78 → row 29.
2. WORST keeps only the largest-|bar| frame, so causes (ii) and (iii) are never held; the report promises they are. In (ii)/(iii) bar reads 0 while visibly low, WORST stays "0 at 0.0s" with the opening numbers; the frames where win dropped 874→845 or the page sprang are lost (real.test.ts test 2). Also past is worked against innerHeight in the frames it moves (a foot spring up to 29 reads past 0 as Chrome's bar grows back). Fix: also keep since the page opened the extremes with times — lowest/highest win, lowest vis height, largest |vis @|, most negative scroll, largest scroll − (page − win) with that frame's raw scroll/page/win — shown as one more line, e.g. `RANGE win 845–874 vis@ 0–29 past −12..30`; the report's sentence changed to match.
3. pinnedRow() checks only the copy's own style, so a copy mounted but not on screen is read as the page's pinned row: on Edit Schedule (no pinned row) a Leave War sticky-head left inside the hidden grid host prints row −49 (real.test.ts test 1). Older-browser path: the war's copy stays mounted at full opacity after leaving the grid pinned (.lw-gridhost hidden; its measure returns early on a 0-height header). Scroll-driven path (likely his iPhone): the copy is always mounted, a dozing Leave War page is display:block; content-visibility:hidden — if WebKit evaluates its scroll-tied opacity there (not proved) a phantom frozen row shows on other pages. Fix: skip an element where !el.closest('.page.on'), or el.checkVisibility && !el.checkVisibility({ visibilityProperty: true }), or el.getClientRects().length === 0; keep opacity > 0.5; a unit test (a copy in a [hidden] host or a page without .on prints no row).
4. The report's table gets the signs wrong for (i): code prints bar = barTop − visTop signed; with the bar at the window's top and the visible screen 29 below (vis @29, Edge's shape) the panel prints WORST −29 (bar hidden above), the opposite of his recording (bar 29 low → bar +29, via the bar's own box or vis @ −29). Fix: state the signs in the report and the file header (bar +N drawn N low — his fault; −N drawn N high, hidden; vis @+N visible screen N below the window's top); rewrite (i) as "WORST about +29 (vis @ about −29, or the bar's own top 29 low)".
