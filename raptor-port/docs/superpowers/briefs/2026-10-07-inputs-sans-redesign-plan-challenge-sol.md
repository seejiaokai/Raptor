CHANGES REQUIRED

1. **§3.7, lines 274–278 — “Keep my changes” can overwrite fields the user never edited.** Open an input, change its remarks, then change its end date through the List behind the window. Keeping the remarks draft and saving through today’s `commitInputEdit` writes the entire old draft, restoring the old end date. Re-running validation does not prevent this. **Fix:** retain the opening image and revision by `iid`; merge untouched draft fields from the live record, and ask about fields changed both ways. Re-check the revision after any blocking confirmation. Add tests for this sequence, record replacement by Undo, and the resulting Undo order.

2. **§3.3, lines 201–203 — the month cache omits inherited records outside that month.** Set Required P to run from 12 January, display March, then change that January start through an open panel. March’s “plan rows in range” have not changed, so its cached Required cells can retain the old figure while the SANS resolver returns the new one. **Fix:** include each seat’s effective predecessor run, overlapping weekday rules, relevant day facts, availability results and SANS Fly commitments in the month’s dependencies. Test changing and undoing an earlier run while the later month remains mounted.

3. **§3.1 and §§3.4–3.6 — the calendars lack a Leave War refresh subscription.** With November visible and another week loaded, add an Off day through Holidays using “Save and add another.” No OIL earning fact or pending OIL question need change. Today’s `wireLeaveWarSync` therefore sends no scheduler notification, and `InputsCal` subscribes only to the scheduler. The calendar can keep showing an ordinary day. Changing an Available row’s filter has the same gap. **Fix:** expose a read-only calendar subscription through `sync.ts` and connect both calendars, Days and open working boxes to it. Cover events, bands, seeded PH flags, periods, count definitions, roster/postings and bid decisions; notify after settled changes and restores without creating notification loops. Test these non-OIL edits without reloading or navigating.

4. **§3.6, lines 248–251 — keeping `data-iid` does not preserve bar dragging.** `caldrag.ts` also requires `data-icdrag` and a containing `[data-icday]`; that containing date determines the move delta. A week-spanning bar has no single correct containing day. Grabbing Wednesday on a Monday–Friday bar either fails to arm or moves from Monday’s anchor instead of Wednesday’s. Its existing landing selector also assumes a chip inside a day cell. **Fix:** specify a coordinate-based date resolver for both press and drop, including continuation segments and landing feedback. Preserve the grabbed-day delta. Add real mouse and touch tests for grabbing the middle of a span, a continuation in the next week, and dropping back in place.

5. **§3.3, lines 194–200 — “These days” wrongly skips weekend, PH and Off cells.** Select two weekend Required cells and apply one number. The plan skips both, although D637 expressly allows a figure authored on those dates to hold for that day. The resolver already supports it. **Fix:** distinguish finite overrides from running figures: “These days” writes selected non-NF dates, including weekends, PH and Off days; running figures skip all four kinds. Recalculate eligibility at Apply and test both operations on the same selected block.

6. **§3.8 and §5 — the timestamp door inventory is incomplete.** Approve leave, then move part of it on the Leave War. `sync.ts:404–451` and `doorMoveApproved` copy or split Input records outside the editor; copied `modBy`/`modAt` would still name the earlier action. The List’s OIL-only revision likewise writes `r.oil` directly without entering `commitInputEdit`. **Fix:** explicitly inventory and stamp these paths, approval extensions, partial un-approval/removal and sick-cut leave pieces, alongside the already named doors. Preserve original `by`/`at` on carried pieces and stamp the actual user change within its existing transaction. Preserve current `mod` behavior so this addition does not alter mode-0 lateness. Test each door and verify Undo/Redo restores recorded timestamps rather than stamping a new time.

7. **§3.3, line 185; §3.2 commands; §3.11 — Required-row renaming has no tracked writer.** `flynames` is introduced, but no rename command or settings registration is specified. Today’s settings capture covers only `SETTINGS_KEYS` and registered prefixes; an unknown key also bypasses automatic command routing. Following the listed changes can leave a rename outside rollback and Undo. **Fix:** name an admin-only writer, add `flynames` to settings capture/records, command registration, permissions and write guards, and define its validation and Undo landing. Add member/raw-write refusal, rename, reload, Undo and Redo tests.

An admin reaching Logic would have to navigate to a calendar to change them. **Fix:** specify two actions opening the same calendar-specific cut-off window and draft/commit path used by the gears. Test opening each from Logic and seeing the change reflected in its calendar and late marks.
