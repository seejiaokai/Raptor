**1. P2 — pending-change details still compare the crowd under today’s settings**

On a published Saturday:

1. Put Bane on “Briefing”, 09:00 with no end.
2. Put ALL AVAIL on “Tasking”, 10:15–17:15.
3. Publish with “Any other row” set to one hour. Bane is free for Tasking and earns OIL.
4. Change that setting to two hours. Correctly, nothing becomes pending.
5. Switch **“No OIL earned” on**.

The pending comparison correctly records the OIL decision. However, its displayed description rebuilds the crowd under today’s two-hour setting. It finds Bane missing and describes **“Tasking · who it stands for — Bane → no longer free”**, instead of the OIL decision. A scheduler reviewing that line can miss that the amendment removes everyone’s earned leave.

The same missed reader adds Logic-only departures to a genuine crowd change. With the brief’s 09:00 ALL AVAIL case, making Pump busy at 09:15 after changing the assumed length makes the detail name both Pump and Bane, although the comparison counts only Pump’s departure.

Cause: [`crowdChange` in pendlist.ts](/C:/Users/User/projects/Raptor/raptor-port/src/ui/pendlist.ts:540) calls `oilEvidence(di)` without the issued settings. Once something waits, validation correctly removes the working copy’s kept settings under D2013. This reader therefore gets today’s crowd, while the comparison producing its item uses `snap.rv`.

This conflicts with D99/D100’s requirement to describe the pending difference, and D2028’s exclusion of a Logic-only crowd change. This is an existing reader missed by the change.

Exact fix:

1. In `crowdChange`, retain the existing current-version lookup.
2. Replace `oilEvidence(di).sent` with `oilEvidence(di, undefined, snap.rv || null).sent`.
3. Leave the working-copy availability window on its existing D2013 path.
4. Add and run both proofs below, red before the fix and green afterwards.
