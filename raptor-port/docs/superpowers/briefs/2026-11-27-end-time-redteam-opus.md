## (2) Routes that sign or publish — checked in the code

**2a. **2b. The sign-off's native list can still open by routes the plan's catch misses.** This is a ruled requirement, via the try-out, and it matters most on his iPhone. Case: with a gap, (i) Windows F4 on a focused sign box opens the popup; (ii) on iPhone Safari, with the keyboard up in a time box, the ▲/▼ arrows above the keyboard move focus to the next control (the sign select) and open its picker wheel; (iii) VoiceOver double-tap opens it; (iv) type-ahead letters change the value without opening (refused later by `signPick`, so safe, but the list behaviour differs). Cause: `signoffHTML` stretches the select "invisibly over the whole pill", so it is always in the tab order and the form-assistant order. `pointer-events:none` plus a filter on Enter/Space/arrows/Home/End stops only mouse, touch and those keys. Fix: while the day has a gap, render the pill without its `<select>` (or with `disabled tabindex="-1"`). Make the label itself `role="button" tabindex="0" aria-disabled="true"`, with click, Enter and Space calling `refuseForTime(di,'sign')`. Keep the change-handler refusal as the backstop. Tests: with a gap, no focusable `select[data-sign]` on the week or the board; in WebKit, focus a time box, then `focus()` the next control, and check no picker or `change` follows.

**2c. The Amendments panel's button would lose its preview lock.** Case: today it is `disabled={!signed || previewing}`. The plan's "lose `disabled` while the day has a gap" enables it while a past version is being previewed. A press then hits the handler's `if (DPREV.has(di)) return` and does nothing, with no note. Fix: `disabled = previewing || (!signed && !gap)`, and a test for gap plus preview.

**2d. The command guard answers for the wrong reason on presses the engine treats as nothing to do.** Case: the plan refuses in `commitSetDayApproved`/`commitPublishALDay` before `fn` runs. So a stale Publish day click on an already-published day says "Thursday was not published." where the engine treats it as a no-op (`SCHED.dayOK[di]`). And Publish AL on a day that is still a draft, or with no changes, gives the time note instead of the engine's "…is still a draft" or "No changes to publish". Fix: guard `commitSetDayApproved` only when `on && !dayApproved(di) && !protectedWeek()`, and `commitPublishALDay` only when `!protectedWeek() && dayApproved(di) && (dayHasChanges(di) || SCHED.correcting[di])`. One test each.
