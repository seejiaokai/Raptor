### Finding 1 (highest consequence: OIL moved by an amendment with no line naming it)

**The failure.** Proof test `zz-opus-read-1.test.ts` (the chat's scratch folder, `opus-read/`). It ran red, 2 of 2.
- **Setup.** The Leave War harness, on the seed Saturday that earns. "Briefing" runs 09:00 with no end and names Bane.
  "Tasking" runs 10:15–17:15 with ALL AVAIL. The day is published with "Any other row" at 1h, so Bane is in Tasking's
  crowd and credited FO.
- **Action.** "Any other row" is changed to 2h. Then a real but unrelated change is made: Tasking is renamed
  "Tasking B".
- **What the app shows.** Edit Schedule's crowd (the preview of the next amendment, D2013) has Bane out.
  `dayPendingItems` lists only `[["content","ap:5.1.prog"]]`, and `dayDelta` is only `["ap:5.1.prog"]`. There is no OIL
  or crowd line. The four sign off on that list. `publishALDay` then freezes the crowd under 2h, and after `runOilPass`
  Bane's FO cell is gone. So an amendment took a man's OIL away while the pending list said only "renamed".
- **What it should show.** D44 says the difference in who stands behind a placeholder raises the ordinary pending mark.
  D592 (4) says a Logic value changed afterwards reads as a pending change and moves OIL only when the day is published
  again. D99 says the list names what moved. So when the working copy shows a crowd that differs from the issued one,
  the pending list should carry the "who it stands for" line naming Bane before anyone signs.

  extension, and the timed-row consequence, are the agent's readings. You may want to put this case to him with the

**The cause.** `publish.ts dayDeltaIn` and `dayPendingItemsIn` always pass `snap.rv` (`oilDelta(di,snap.d,snap.rv)`, and
`oilNowAs(di,snap.rv)` twice). The crowd comparison therefore always runs under the issued settings. But once anything
else waits, `validate.ts untouchedKept` stops laying the kept settings. The screen (`oilEvidenceOf`,
`ui/pendlist.ts crowdChange`) and the amendment (`daySnap`, which passes `null`) then use today's. The comparison and
the thing it describes run under different settings.

### The fix (both findings)

1. In `engine/publish.ts`, add one helper, `crowdRvFor(di,snap)`. It returns `snap.rv` only when **nothing else waits**
   on the day, and `null` (today's) otherwise. "Nothing else" must be the same test `validate.ts untouchedKept` uses
   minus the OIL entries: `canonicalDiff(snap.d,DAYS[di],di)` is empty; the input axes (`ax.fil`, `ax.val`) are empty;
   the filing and frozen-input checks pass; no hide is waiting; `snap.pa` matches; there is no brief-lead difference.
   Better: move those non-OIL checks out of `untouchedKept` into one exported function both callers use, so they
   cannot drift.
2. In `dayDeltaIn`, build `canonicalDiff…concat(ax.fil).concat(ax.val)` first. Then call
   `oilDelta(di,snap.d,crowdRvFor(di,snap))`.
3. In `dayPendingItemsIn`, use the same value for `oilDelta(...)` and for both `oilNowAs(di, …)` calls (the `moved`
   fold and `nowSent`).
4. Leave `ui/pendlist.ts crowdChange` as it is. Once the day is not untouched it already reads today's, and with the
   fix the line's existence and its words come from one set of settings.
5. Add a guard so that `untouchedKept` calling `dayDeltaCore` cannot recurse: the helper must not call `dayDeltaCore`
   or `oilDelta`.
6. Tests to add: my two cases; the existing "put back" cases must still read `[]` (with nothing else waiting,
   `snap.rv` is used again, so D98 holds); the existing "Logic change alone" cases are unchanged.

### Tidiness note (filed, not fixed)
- `oilEvidence`'s third argument has three meanings: a value, `null`, or left out. On top of that, `oilNowAs` turns a
  missing `rv` into `null` with `rv||null`. Calling it without `rv` therefore silently means "today's", not "laid", and
  that is easy to misuse. A named option such as `{crowd:'kept'|'today'|'laid'}` would read better.
- `keptRulesOf` is a second exported name for `keptOn`, which does the same thing.
- The `oil.ts` file header still says the block reads today's through `ruleNow`, while `openEndRows` now reads plain
  `VCONF` under a laid overlay. The header now misleads.
