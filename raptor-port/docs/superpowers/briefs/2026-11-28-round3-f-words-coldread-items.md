# Eight lines for a cold read (28 Nov 26) — given to the reader alone

A squadron's scheduling app: Edit Schedule (the week's programme of flights, sims and ground items, with a warning
list), the Inputs page (leave, duties and other commitments people file), the Leave War (leave and OIL balances), the
Logic page. Each item: where it sits, what is just above it on screen, then the line exactly as a person sees it.

## The app's own words used below (its word list)

| On screen | What it means |
|---|---|
| OIL | Off in lieu: earned or granted time off, held as a leave balance. |
| Leave War | Plans leave and shows its effect on balances and available people. |
| Inputs | The page for filing and reading leave, medical records, duties and other commitments. |
| Accept / Reject | Puts an eligible input back onto the programme or leaves it inactive until accepted again. |
| Publish day | Issues the day's first published version after its required sign-offs. |
| Working copy | The editable day, including changes that viewers have not yet been issued. |
| Warning | A scheduling finding; red warnings, amber advisories, grey notes. |
| Conflict | A man booked on two things at once — every such warning line starts "Conflict:". |
| Hide this warning / Flag this again | Stops or restores a particular warning's visible flags while retaining its line in the list. |
| [A person's puck] | The small name tile used to show, select or place a person. |
| Logic | Shows the scheduling settings and explains the checks that use them. |
| SANS availability | Offers from SANS aircrew to fly or attend simulators during stated times. |
| Upchit | A record that the person has been medically cleared to fly again. |
| CX | Cancels an item while leaving its cancelled line visible. |
| Info only | Shows an item without checking it against the scheduling rules or earning OIL from it. |

## The lines

**1.** The Leave War. An admin taps Hunter's Sat 18 Jul, which shows OIL earned. A card opens; under the label
"Where it came from":
> Earned off the published schedule. Change the schedule and publish the day again, and the OIL follows.

**2.** The same card for another day, whose OIL came from an input. Under "Where it came from":
> Earned off a duty input that was accepted. Change that input and publish the day again, and the OIL follows.

**3.** Edit Schedule's warning list. Above it, the warning line "Conflict: Ranger — VL SAT 12:45–14:15 & LECTURE
13:00–14:00". Beside it a small ✕; resting the pointer on the ✕ shows:
> Hide this warning — it flags no puck and is not counted; it stays hidden while the same man is on the same two items, even if their times change

**4.** The scheduler presses that ✕. A passing note appears at the foot of the screen:
> Warning hidden: no flag, not counted. It stays hidden while the same man is on the same two items, even if their times change.

**5.** The Logic page. Under the check named "An input closes its hours":
> On the working copy an input closes the man for the hours it covers, from the moment it is filed. SANS availability and an upchit close nothing, nor does an input a scheduler takes off the programme, cancels (CX) or marks information only.

**6.** The Inputs page. Hunter, a member, tries to change a duty input that Ranger filed for Ace. A passing note:
> Only Ace, Ranger (who filed it) or an admin can change this input

**7.** The same, when Hunter tries to delete it:
> Only Ace, Ranger (who filed it) or an admin can delete this input

**8.** The same, for an input Ace filed for himself:
> Only Ace or an admin can change this input
