## What is built

- **`state/guard.ts setEntryChecker(fn | null)`**, a no-op unless a test set-up installs one.
  - Each `refuse()` that passes hands it the leave: the door and its `skip`, good for the synchronous turn.
  - Each `refuse()` that refuses hands it the rows open at that moment.
- **The two checks (§3.4):**
  1. `enterSquadron` with `byPick` true, and `switchRoleInForce`, ask the checker first. It asks `refusalAt` again,
     with the leave's `skip`, or with none where no door gave a leave. If that refuses, it throws an error naming the
     open row and the door.
  2. At the end of a refusing turn (a microtask), a counted row that is open now and was not at the refusal fails the
     test by name.
- **Install it in the global test set-ups** (`src/testing/` and `src/leavewar/test-setup.ts`), importing `ui/guard` so
  the guard answers in the headless state tests too.
- **The allow-list lives in the checker's own file.** It names each test that drives a raw entry or the raw switch
  with something open on purpose, with the reason. Match it by the test's full name
  (`expect.getState().currentTestName`) or by an explicit flag the raw helpers set. **Prefer the flag:**
  `switchRoleViewRaw` and a raw entry made through one named test helper set "this entry is raw on purpose" for that
  turn. The list then only names tests that call `enterSquadron(…, true)` themselves. Say which you chose and why.
  Build 2 empties the list.
- R5 (a) (a pin: the list of door callers as it stands now) and R6 (the checker fires), in
  `src/ui/msq-guard-rollcall.test.ts`, tests first, R6 seen failing.
- Its limit, said in a comment and not tested for: a change through `maybeReenter` (`byPick` false) is invisible to it.
- Not the app's behaviour, not a word, not `src/ui/UsersPanel.tsx` or `AdminPage.tsx`, not `storage/`. If a test it
  fails needs a change in the app to pass, **stop and report it**: that is a finding about a door, never silenced.

1. `node raptor-port/scripts/gatelock.mjs take "claude/msq-s1-guard-6ae5e1 — K7, the full unit suite with the checker on"`.

For every test the checker fails, decide which it is and say so in the report:
- **(i) a test that makes a state no press can reach any more, on purpose.** It joins the allow-list, by name and
  reason, or is re-pointed to the raw helpers that set the flag. Every assertion is kept.
- **(ii) a test that shows a door the plan missed.** Stop on it and report it: a finding for the orchestrator, never
  allow-listed to make the suite green.

Never weaken or delete an assertion.
