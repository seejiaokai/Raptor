# D999 — the code survey before the build (the night of 18 Oct 26; a read-only helper, saved as returned, condensed)

**The ruling:** an upchit moved to a later date gives the downchit it cut its days back to the day before the new date,
never past its own first end, said on the upchit's save sheet; a calendar drag the same.

1. **The cut:** `src/engine/medical.ts` `upchitTrimPlan(person, xOrd, except)` finds each downchit covering the upchit
   date X and plans it through `trimTo` — the new end X−1, or `delete` where X−1 falls before its start;
   `upchitEffects` returns `{plan, leftovers}`. Applied in `src/ui/inputedit.tsx` `applyMedPlan`: a trim overwrites
   `r.endDate` in place, sets `mod`, `stampChanged`, `elogReason(r.iid, 'cut by a medical')`; a delete through
   `dropInputRow`. **Nothing on the record keeps the end it had before** (only the change log and undo's copies).
2. **The save sheet** `src/ui/UpchitConfirm.tsx`: the trim list ("<type> <span> → now ends X−1" / "→ removed"); with no
   plan "Close the pending medical-down period — no current entry needs shortening."; "Fit for full duty from …";
   Keep / Remove for each leftover. No wording for a downchit growing back. From the window: the refusals, then
   `setUpConf({…effects: upchitEffects(person, isoOrd(start), isNew ? null : r)})`; Save is `doSave(removals)` —
   `commitInputEdit` and the removals in one `saveBatchX`. From a calendar drag: `src/ui/caldrag.ts` → `medAskFor` →
   `setMedMove` → `src/ui/MedMoveConfirm.tsx` draws the same sheet; Save is `commitEditUpchit`. Cancel writes nothing.
3. **Moving it:** both paths re-run `upchitTrimPlan` at the new date, the upchit excluded. Earlier: cut further (works).
   **Later: the downchit already ends before the new X, so it is skipped — nothing grows back, the sheet says "no
   current entry needs shortening", and the days between read fit.** Edge: a cut that deleted the downchit (an upchit on
   its start day, or a one-day row) leaves no row to grow back.
4. **Stored:** fields in `docs/data-schema.md` §Inputs, `src/engine/schema.ts` type `Input` (pinned to the seeds by
   `schema.test.ts`), the table `docs/data-model.md` §Input. No per-record version (recent optional fields `till`,
   `title` added without one). A new field needs all three in the same change (D473).
5. **Tests:** `engine/medical.test.ts` (`upchitTrimPlan`, `upchitEffects`), `ui/medwrite.test.ts`, `ui/upconfirm.test.tsx`,
   `ui/medmove.test.tsx`, `ui/windowreads.test.tsx`, `ui/savesaysok.test.tsx`, `ui/latepub.test.tsx` F1,
   `leavewar/whoplaced.test.ts`, `state/undo-wire.test.ts`, `leavewar/scenarios-rules.test.ts`. **No test moves an
   upchit later.**
6. **Undo:** the cut is one command with the save — one Undo restores both; `medPlanProtected` refuses a plan touching
   protected dates whole.
