**How to read the columns**

- *The rule* is quoted from the rulings page (`.claude/rules/decisions/scheduler.md`, `oil.md`, and where marked the Leave War and People pages), trimmed with "…" only where long, the bracketed ruling numbers moved to the next column; two statements joined in one cell are joined by "and". Where the page has no statement, the cell says so and quotes the full row or `engine-rules.md` — those quotes are shortened and lose their code marks, so open the line given before leaning on a word.
- *D-numbers*: first the rulings that carry the rule; "beside it" are the others the page cites on the same statement (look, place, later carriers). A ruling may carry a rule on more than one item.
- *Where implemented* and *tests naming it* were filled by a search of `raptor-port/src` and `raptor-port/e2e` for the number itself, by the same test the document gate uses (a `.test.` or `.spec.` file, `.ts` or `.tsx`, that writes the number). A function name is the nearest one to the comment and can be wrong by one. "By file name" marks tests found by subject, not by number. A ruling built without its number in a comment shows as "not found" — that is a place to search by subject, not proof it is unbuilt.
- *Agent's reading* in a note means the full row marks that part as the agent's own reading, not his words.
- STALE candidate, MISSING, DRIFT in a note are the method's four kinds (`raptor-port/docs/superpowers/briefs/rules-first-red-team.md`), given as where to look — none was checked.
- Open a full row with the shell: `grep -h '^| D592 |' .claude/decisions-full/*.md` (an archived one: `grep -h '^| D591 |' DECISIONS-ARCHIVE.md`).
