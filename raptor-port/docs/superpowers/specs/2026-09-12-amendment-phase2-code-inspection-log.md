## HIGH
- **P2-IMPL-01 · sync.ts:833 — OIL credits are NOT preserved for unsupported/wrong-week books.** Null resolution falls back to the live/stashed DRAFT, not the issued content; if the draft dropped a duty the desired map omits the credit and `runOilPass` DELETES it, and a wrong-week book is credited under the outer week key. My "credits stand via fall-back" claim was wrong. **Fix:** classify live+stashed books in the OIL wire, carry protected dates through reconciliation, forbid credit updates AND deletions for them; never substitute draft content for unsupported issued evidence.
- **P2-IMPL-02 · store.ts:490 — an unsupported book is NOT preserved byte-for-byte.** It still runs `migrateLegacyIds`/`backfillSnapshotIds`/`migrateBookKeys` on load, then `loadWeek` replaces its stash and `persistAll` writes the reconstructed snapshot — overwriting the original recovery evidence. My amformat test only serialized `schedFields` directly and bypassed this pipeline. **Fix:** retain the original blob separately, bypass migration/normalization/writeback for it, and test preservation through hydration→navigation→unrelated save.
- **P2-IMPL-03 · store.ts:533 — read-only quarantine is incomplete.** It lives only in `editMode()`; the Inputs page + `inputedit.tsx` accept/unaccept/edit and `slots.ts` input paths don't check protected dates, so editing an accepted input's times on an unsupported week mutates+persists a ground row despite quarantine. **Fix:** protected-week/date checks at input create/edit/delete/accept/replace entry points (both source and destination dates), reflected in the UI.
- **P2-IMPL-04 · store.ts:388 — a pre-deployment saved DRAFT goes read-only after its first publish.** An old unstamped-but-empty book passes as `current` (editable), but `setDayApproved`/`alIssue` never stamp `amV`, so the moment it publishes its first day it becomes `unsupported` and `editMode` disables it. **Fix:** stamp `amV=AMBOOK_VERSION` when a validated unstamped-empty book first publishes (or normalize it on load); keep quarantine only for content-bearing legacy/unknown books.
- **P2-IMPL-05 · store.ts:406 — the filing fingerprint's 'u' state isn't preserved across navigation.** `loadWeek` deletes all `acc` except `'r'`, and no ground row reconstructs a filed-unavailable input, so navigating away and back makes the live fingerprint read fresh while the issue still holds `'u'` → an amendment appears from navigation alone (or a pre-issue filing is lost). **Fix:** persist the live filing state independently of ground-landing reconstruction; restore all four states across navigation/reload.
- **P2-IMPL-06 · canonical.ts:175 — `canonicalDiff` misses new addresses on SURVIVING rows.** Appending a person to `who[]`, an overflow `more[]`/`pax[]` slot, or a newly-appearing `bxr` reason changes no row identity → empty diff, while the digest still flips → an AL is issued with `diff:[]`/zero items and recovery derives `nd=0` and can discard the work without confirmation. Breaks the `dayHasChanges ⇔ dayDelta` invariant I relied on. **Fix:** detect canonical address additions/removals on surviving rows (incl variable-length crew slots and optional fields).

## MEDIUM
- **P2-IMPL-07 · publish.ts:206 — the digest fast-path isn't equivalent to the normalized delta.** A ground reorder whose effective display order is unchanged flips the positional digest → `dayHasChanges` true (zero-change AL enabled) while the panel offers no publish. **Fix:** derive `dayHasChanges` solely from the full `dayDelta`; use that one result for eligibility, counts and storage.
- **P2-IMPL-08 · drafts.ts:489 — canonical-only edits lose mark attribution.** Changing a cancelled-duty reason via Save-reason marks `dr:role` (composite excludes `cxr`); `reconcileIssuedMarks` drops it, and `alIssue` copies pending marks rather than generating them from the diff, so the revised reason gets no AL attribution. My "P2-07 needs no change" call was wrong here. **Fix:** associate marks with all relevant canonical fields (or emit synthetic marks), and extend reconcile+rebase.
- **P2-IMPL-09 · html.ts:1029 — the recovery confirmation shows "Discard 0 edits".** I fixed the handler's arm count but the button renderer still reads `dayPendCount` inside `withDaySnap` (which clears pending). **Fix:** capture the live delta count before entering `withDaySnap` and pass it into the preview renderer.
- **P2-IMPL-10 · board.ts:1277 — the template-apply confirm arm isn't week/edit scoped.** `DAYTPL_ARM` is keyed only by day-index+template-id, so the same template id on another week matches the stale arm and replaces that week's edits without its own confirmation. **Fix:** bind the arm to the absolute date + template revision + working-draft revision; invalidate on navigation/edits.
- **P2-IMPL-11 · board.ts:1286 — template apply doesn't disarm an armed crew slot.** Unlike recovery/draft-switch, it relies only on `afterSchedMutate`, so a stale arm can plant into the replacement sortie. **Fix:** disarm the day's slot before template replacement.
- **P2-IMPL-12 · publish.ts:119 — `dayCurVerIn` validates only the highest-seq record.** It picks the highest seq then validates just that one, so a higher-seq wrong-week/inconsistent record makes it fall through to Original instead of a valid AL1. **Fix:** iterate candidates by descending seq and return the highest that VALIDATES through `daySnapIn`.
