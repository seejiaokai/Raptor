Q9. A save that never gets an answer, then a pick

The app stops waiting after a set time and shows "Not saved" with Retry, as it does when a save is refused. The pick is then refused with the Retry note.

When this happens: rarely. Only when a change is sent to be saved and no answer ever comes back, as when the connection drops mid-save. Saber changes a day, then picks 149 while the change is still saving.

Why ask: you ruled a pick waits for a save in flight, then goes or is refused. Today the app keeps a save that never answers "Saving…" for ever, so the pick would wait for ever.

Recommended: after a set time with no answer the save gives up and shows "Not saved" with Retry. The pick is then refused: "Blocked: press Retry to save your changes, then pick 149." This changes saving everywhere in the app, not only at a pick, so it gets its own test and its own check.

The other choice: no waiting. While "Saving…" shows, a pick is refused at once with a note of its own (its words still to be drafted).
