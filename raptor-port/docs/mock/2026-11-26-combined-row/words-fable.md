No file changed. Nothing here has had the cold read (§1b test 11) — 2 and 3 carry an instruction and need one.

## What applies to all three "Blocked:" notes

- **No full stop on a one-sentence note** (§1b test 4). The app's own: "Blocked: that change is not yours to make",
  "Blocked: Ranger is 149". Drafts 1, 2 and 3 each end with one — drop it. A note of two sentences ends each with one.
- **"him" goes.** The app's notes say the callsign or "person" / "who is in it" ("Open this input's own window to
  change who is in it", "take that person off the list"); "him" appears in one note only. And the dropped puck may be
  ALL or ALL AVAIL, which is not a "him".
- **The dropped man is not named.** The family names him only where the fact is about him ("Blocked: Ranger is 149",
  "Ranger is already on this input"). Here the fact is about the row, and he has just let go of the puck.

## 1. Drop on a medical row

- Draft: "Blocked: a medical is always one person's."
- **Adjusted: "Blocked: a medical entry is always one person's"**
- Why: the app's own name is "a medical entry" ("A medical entry stays medical…"), not "a medical"; full stop off.
  Fact, "always" and "one person's" kept as he ruled (D2776: short, says why).
- To note: today this same drop REPLACES the man ("Hex is now unavailable instead of Ranger"). A scheduler used to
  that gets a reason but no way through. If the builder wants the remedy (§1: a refusal's way to put it right), the
  longer form is "Blocked: a medical entry is always one person's. File Hex a medical entry of his own with + Medical."
  — longer, names the man, and "+ Medical" must be checked as the door. My pick stays the short one: his ruling asked
  for a short note saying why.

## 2. Drop on a Personal Inputs line whose input is on the Ground Programme

- Draft: "Blocked: drop him on this input's row on the Ground Programme."
- **Adjusted: "Blocked: change who is in this input on its Ground Programme row"**
- Why: the draft is an order with no reason and a "him". This one says what is and what works in one sentence
  (§1b test 6), in the words of its nearest relative ("Open this input's own window to change who is in it"), and
  covers both add and replace (D2772) without saying "drop", so it is still true for an ALL puck. Same length.
- **Would mislead — for the builder, not a wording matter:** on the Board, a puck dragged from a row over the
  Personal Inputs panel shows "drop to unassign" and letting go takes that man off his row (the survey; D2773 keeps
  it). If the same let-go can also raise this note, the scheduler reads "unassign", then "Blocked". Say which drops
  are refused (a puck from the people list only?) and make sure no drop both unassigns and says Blocked.

## 3. The same, the input waiting or rejected (no Ground Programme row)

- Draft: "Blocked: put this input on the programme first."
- **Adjusted: "Blocked: this input has no Ground Programme row yet. Accept it first."**
- Why: (a) "the programme" is not a name — there is a Ground Programme and a Common Programme; (b) "first" promised
  that the drop would then work HERE, and it never will (draft 2 refuses it) — the reason "no Ground Programme row
  yet" now says where the drop belongs; (c) "Accept" is the button on the line, so the note uses the button's word
  (§1: one name for one thing). Two sentences, a full stop each. Marked **longer**: 11 words against 8.
- For the builder to check before it is built — each a fact I could not settle from the words:
  - a REJECTED input's button really reads "Accept" (if it reads otherwise, the note takes that word);
  - a waiting input whose Accept sends it under Unavailable (a course, an overseas duty, an Attach, an Other set to
    Unavailable) — for those "Ground Programme row" is false. They need "…has no row on the schedule yet. Accept it
    first." or the note is raised only for Ground-bound kinds;
  - who sees it: only a scheduler can drop, so "Accept it" is always his to press.

## 4. The button on a group leave's line in the Leave War's bid window

- Draft: "Change for all 3"
- **Adjusted: "Change for all 3 people"**
- Why: on a leave line that also shows its dates ("Mon 19 – Wed 21"), "all 3" reads as all 3 days as easily as all
  3 people. The app's own question says "Delete this input for all N people?" — same family, same words. Verb first,
  and the cost (everyone changes) stays on the button, which matters because there is no "his only" choice (D2778).
- To note: for a group of two, "Change for both people" — "all 2" is not said. If the line is too narrow at his
  iPhone's width, measure the box first (§1a test 1); the fallback is the draft as written, with the people's pucks
  or names on the same line settling "3 what".

## 5. The shared mark on a group entry's Leave War box

- Draft: "3·LL"
- **Keep: "3·LL"**
- Why: same count, same dot, same order as the Inputs calendar's "3 · LL" — one mark, one look; only the two spaces
  go, and the 20px box is the reason (a named, measured departure, to be shown to him in the drawing D2778 asks for).
  A middle dot between two facts that are not sentences is allowed (§1b test 2).
- To note:
  - measure the worst case before it is drawn: a three-letter code and a two-figure group ("12·CCL", "10·OIL") at
    7px letters will not fit 20px — decide what gives (the count stays; it is the warning);
  - on the Leave War a number in a box otherwise means a count of people out or a figure, so a first-time reader may
    take "3·LL" for three days. The box's hover / long-press line and what a screen reader is told should say it in
    words: "LL, shared by 3 people" (the agent's wording — to draft with the drawing);
  - the Legend carries the mark's meaning (§1: what a mark means is the Legend's).
