**F1 · A course copied between squadrons shares its remembered student and chart · medium-high · new with D2395.**
Saber copies a course from 142 to 149 by Export and Import. Choosing student JRBRAVO on 142's copy makes 149's copy reopen
on JRBRAVO, not the JRALPHA left there, so his next mark would go on that student unless he reads the name. Choosing chart
2024 on 142 makes 149 reopen on 2024 with an empty Crew box and "No students on this course yet." Nothing is lost: picking
2026 brings them back. It survives a sign-out. Cause: `tracker/app/core.js` files the remembered course per squadron
(`lastCourse@<unit>`) but the chart and student per course only (`lastSyl:`, `lastCrew:`), and an import keeps the course's
id. Fix: file those two per squadron as well. Picture: `host/repro-now/j06r-d/02-149-chart-after-142-chose.png`.

**F2 · In the member view with unsaved chart edits, a pick looks dead · medium · new tonight (read from the code: the old
check did not ask here; the same presses could not be run on the older build, whose Tracker does not follow).** Hunter has a draft on 149's

`useCover`), and `TrkAskOnly` shows only the section, so the question inside stays hidden; tonight's wider
`movesTrackerAway` (`state/pick.ts`) makes this pick ask. Fix: let the question show through the cover while it is up.
Pictures: `host/repro-now/s24d-d/01-after-dead-pick.png`, `03-stale-question.png`.
