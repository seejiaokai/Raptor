## What the walk found

**One fault, fixed:** the first build drew the claw with SVG masks, which a browser works out on the page's own thread.
On a phone-like load (the processor slowed 4x, a phone's 4G) the app's code kept that thread busy from 0.73 s to 1.66 s,
so the claw never showed at all (case H's record). Rebuilt with sliding windows — each claw in a narrow window laid
along it, the window sliding down while the claw inside slides back — which a browser keeps moving while the page is
busy: case K, the page held busy 1.5 s, the screen drew 53 frames with 39 different claws. The whole claw still matches
the logo (case I: no pixel off by more than 166 of a possible 450 — a softened edge along one side of each claw, mapped
in `walk/I-diff.png`; a missing part would show 450).

**Not faults (the walk's own tools):** a screenshot stalls Chromium's frames (186 ms), which first read as the middle claw
starting 15 ms after the left — the pictures now come from a run of their own; a reload never keeps a sign-in in this
app, so case E's first form waited for a schedule that does not come after a reload. WebKit's Windows build takes about
3 s over a picture and cannot picture a paused frame, so WebKit's timing is case B's frame record and its picture
`walk/B-webkit-phone-2931ms.png` (the claw whole, its light round it).
