## What the breaks showed — said, not chased

**No test was already red.** Every wide run with nothing broken-and-caught came back fully green.

**1. Two of the door's five "only a scheduler" tests change nothing when they are dropped (rows 11d, 11e).** With the
test gone from `rowLeaveTo` and from `rowMark`, a member who filed the input is still refused, and nothing is written:
something behind the door already stops him (for a mark the door's own comment names it — the member's save gate,
`state/perms.ts`; for the seat I saw only that the drop comes back refused, not which line refuses it). Not a fault —
two locks on one door — but those two lines are not what keeps a member out. The other three (put, taken off, moved)
ARE the only thing between a member who filed an input and the same change made by a hand on the schedule, and no test
held them: the existing "A MEMBER … changes nothing by any of these hands" uses a member who is in the input but did not
