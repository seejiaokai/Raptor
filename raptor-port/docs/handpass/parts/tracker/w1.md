## 2. Every finding, in plain words

**W1-1 — Export leaves out unsaved chart edits, and does not say so. CONFIRMED.**
What a person sees: he adds a ball and a prerequisite in chart-edit mode, finishes editing, and
exports. The Export window opens with no warning. After the wipe and import the ball is gone — the
file never had it. Steps: 2026 → Syllabus ✎ → ✎ Edit chart layout → + Flight "LATE-1" → Connect,
ST-01 then LATE-1 → Syllabus ✎ → ✓ Done editing chart (orange ✓ Save changes stays lit) → ⇪ File →
⤓ Export…, tick every chart → Export → fresh browser → ⇪ Import… → Replace ×4 → 2026 has no LATE-1.
Should: either the file holds the chart as it stands, or Export asks to save first (as the Syllabus
dropdown asks before a switch). Where: `collectCharts` reads `sylSource(id)` — the SAVED definition
(`src/tracker/app/core.js` ~4688–4700); `openCopy` (~5040) and `saveCopyClick` (~5050) never look at
`sylDirty`. By reading (walked: the new ball and its link only): moved balls, drawn lines,
arrowheads, merges and fonts save themselves the moment they are made, so they DO reach the file;
what is lost is the structure held back for ✓ Save changes — events added, deleted or re-typed, and
prerequisite links.

**W1-2 — + Add syllabus, ⧉ Duplicate syllabus and ⇪ Import throw unsaved chart edits away without the
question the Syllabus dropdown asks (R88); after an Import the orange ✓ Save changes stays lit over a
chart with nothing unsaved. CONFIRMED.**
Steps: leave an unsaved ball on 2026 (as W1-1), then (a) Syllabus ✎ → + Add syllabus → name → OK →
back to 2026: the ball is gone, never asked; (b) Syllabus ✎ → ⧉ Duplicate syllabus → OK: the COPY
gets the unsaved ball, saved; the original 2026 silently loses it; (c) ⇪ File → ⇪ Import… any charts
file → Replace: the ball is gone AND ✓ Save changes is still orange (pressing it would "save" a chart
with nothing to save). Should: each asks "You have unsaved flow edits on “2026”… Discard them…?"
first, as the dropdown and the Course ✎ commands do. Where: `addSyl` (~4352) and `dupSyl` (~4319) never
call `leaveFlowEdits`; `switchSylNow` (~4261) runs `clearDirty()` and reloads; `dupSyl` copies the live
chart (`SYL`, with the unsaved edit) into the copy (~4332); `importClick` (~5166) has no check, and
`applyCharts` ends in `loadCourse` (~4804) without clearing `sylDirty`.

**W1-3 — On the database route, a chart whose balls were never dragged comes back with every ball
stacked in the top-left corner. CONFIRMED — this is the D120 path.**
What a person sees: after export → wipe → import, the chart shows one ball; all the others are
underneath it. Steps: Syllabus ✎ → + Add syllabus "SKETCH" → ✎ Edit chart layout → 📋 Edit events →
paste two events → Save → ✓ Save changes (don't drag them) — or Duplicate 2026 and press ↺ Reset
layout on the copy — then switch to another chart, Export every chart, wipe, Import: SKETCH shows 1
