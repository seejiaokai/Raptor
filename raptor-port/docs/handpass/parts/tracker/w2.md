## 2. Every finding

### W2-F1 — The "cannot be failed" message for an N.A. event is never shown — CONFIRMED
**What a person sees:** on an event marked N.A., pressing + in its pop-up does nothing at all — the
count stays, no words appear anywhere. The refusal is written to the edit-mode hint line, which is
hidden unless the chart is being edited.
**Steps:** tap ST-02 → N.A. → tap ST-02 again → press + (Fails).
**Should see:** "“ST-02” is marked N.A., so it cannot be failed." (R52).
**Where:** `core.js` `popFail` → `flashHint` → `#arrhint`, shown only with `arrangeMode` (`App.jsx`).
**Note:** this is the "hidden flash line" item in the host's commit `5322db46` — already changed
in source, not in the build I walked. Re-walk after the rebuild.
Picture: `w2-04-na-plus-pressed.png`.

### W2-F2 — Re-typing a done flight's "Done on" day puts TODAY into Last Flown — CONFIRMED
**What a person sees:** a flight marked done on 15/09; they correct its day in the pop-up to 17/09.
The mark reads 17/09, but both Last Flown boxes now say **23/09 (today)**, "Days since syllabus 0d",
"Landing Current — No IP Required", "Current — no flex required" — although nobody flew today.
**Steps:** tap TR-2 → type 15/09/2026 in "Done on" → DCO. Tap TR-2 again → click the day part of
"Done on" → type 17092026.
**Why:** while a date is typed, the box is empty for a moment (after the "0" of "09" it holds no
full date — recorded values: 2026-09-01, 2026-09-17, **""**, 2026-09-17, 0002-09-17, …). The app
treats an empty "Done on" as today, re-dates the flight to today for that instant, and Last Flown —
which only ever moves forward (R50) — jumps to today and stays there.
**Should see:** Last Flown 17/09 (R47, "a flight's day is its Last Flown").
**Where:** `core.js` `popDoneChanged` → `setDoneDate(s, popId, v || isoToday())` → `flownOn`.
Any day or month typed with a leading 0 does it. Pictures: `w2-02b-retyped-day-lastflown-today.png`,
`w2-02b-currency-card-says-today.png`.

### W2-F3 — Correcting or taking back a flight leaves Last Flown on a day nobody flew — CONFIRMED (the rule is his call)
**What a person sees:** (a) TR-2 marked done today; the day corrected in the pop-up to 21/09 (typed
in one go) — Last Flown stays 23/09 ("0d") though the only flight was on the 21st. (b) TR-4 marked
done on 24/09 (tomorrow), then set to N.A. — Last Flown stays 24/09 and the card reads "Days since
syllabus −1d", "Landing Current".
**Steps:** (a) TR-2 → DCO → reopen → type 21/09/2026 in "Done on". (b) TR-4 → type 24/09/2026 →
DCO → reopen → N.A.
**Why:** Last Flown only moves forward (R50 — so marking an OLDER flight afterwards never drags it
back, which is right). But the same rule also blocks a CORRECTION of the flight that set it, and
taking that flight back. The boxes can be retyped by hand (R50), but nothing on screen says so.
**Should see:** per R47, Last Flown = the latest flight still marked done.
**Where:** `core.js` `flownOn` (forward-only), called from `setDoneDate` and `popGrade`; nothing
recomputes it when a flight is re-dated earlier or un-marked.
Pictures: `w2-02-tr2-redated-back.png`, `w2-02-after-na-lastflown.png`.

### W2-F6 — ↶ / ↷ throw the chart back to its top — CONFIRMED
**What a person sees:** scrolled far down the chart to BFM-3, they grade it (the view stays, R62),

**Steps:** scroll the chart to BFM-3 → tap it → DCO → ↶.

marked, so the chart must not move under you". Picture: `w2-08-view-after-undo.png`.

### W2-F7 — A new ball given a deleted ball's code comes up already graded — CONFIRMED (the fix direction is his call)
**What a person sees:** ACG-03 (A: DCO and one failure; B: DPCO) is deleted in the chart editor,
Save changes, reload — gone. Later a new academic ball is added and named "ACG-03": it appears
already graded for both students; its pop-up says "Done on 23/09/2026", "Fails: 1 — ACG-03
23/09/26"; the Overall card counts it as done. Still so after Save changes and a reload.
**Steps:** mark ACG-03 for A (+ once, DCO) and B (DPCO) → Syllabus ✎ → ✎ Edit chart layout →
🗑 Delete → press ACG-03 → OK → ✓ Done editing chart → ✓ Save changes → reload → ✎ Edit chart
layout → + Acad → name "ACG-03".
**Should see:** a new event starts with no marks (Astra #29: "permanent deletion must not make old
marks silently reappear on a later same-id event"). The delete question says only "Delete ACG-03
from this syllabus?" — nothing tells the person the marks are kept and would come back.
**Why:** marks are filed under the event's CODE; deleting the ball removes the event, its arrows
and its place, but not the marks, so any later event with that code picks them up. (Keeping them
is also why ↶ of a delete brings the marks back — so the fix is a choice: delete the marks with
the ball and have ↶ restore them, or keep them and say so / offer them back openly.)
**Where:** `core.js` `deleteEvents` (touches events, lines, layout, fonts, arrows — no marks);
`addModule` (refuses only a code that is on the chart NOW).
Pictures: `w2-10-new-ball-same-code.png`, `w2-10-new-ball-after-reload.png`.
